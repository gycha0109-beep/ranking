# P1-2.8 관리자 권한 분리·고위험 운영 감사 설계 리뷰

## 리뷰 결론

역할 계층을 capability 계약으로 분리하는 방향은 타당하다. 기존 `admin` 의존 코드와 RLS가 넓게 퍼져 있으므로 `super_admin`이 기존 `admin` implied-role을 함께 보유해야 하며, `moderator`는 `admin` 행을 가져서는 안 된다. 독립 리뷰 결과 모더레이터의 초기 권한 범위와 역할 변경 동시성 보호를 추가 축소·강화했다.

## 발견 사항과 보완

### 1. 기존 admin 호환성

기존 admin 행을 단순 교체하면 CMS가 잠길 수 있다. 기존 관리자에게 `moderator`, `admin`, `super_admin`을 모두 유지하고 이후 역할 변경도 정규 implied set으로 재구성한다.

### 2. 모더레이터 권한 과다

초기안은 댓글 신고와 제재 조회까지 모더레이터에게 허용했다. 신고 결정은 작성자 경고 원장까지 생성하며 제재 정보는 민감하므로 최종 범위를 다음 두 capability로 축소했다.

- `admin_console_access`
- `moderation_review`

신고 검토, 제재, 감사, CMS는 관리자 이상이다.

### 3. `is_admin()` 의미

`is_admin()`을 운영자 전체로 확장하면 모더레이터가 기존 CMS RPC와 RLS를 통과한다. 최종적으로 `admin | super_admin`만 참이며, 모더레이터 허용이 필요한 댓글 Moderation 함수와 RLS만 capability 기반으로 전환했다.

### 4. implied-role 불일치

직접 table write가 남으면 `super_admin`만 있고 `admin`이 없는 상태가 생길 수 있다. API 역할의 `user_roles` 쓰기 권한과 관리자 write policy를 제거하고 역할 변경 RPC만 정규 역할 집합을 작성하도록 했다.

### 5. 마지막 최고 관리자 경쟁 조건

대상별 lock만 사용하면 서로 다른 최고 관리자를 동시에 강등하는 요청이 마지막 관리자 조건을 각각 통과할 수 있다. 구현 리뷰에서 이를 발견해 모든 역할 변경이 동일한 전역 advisory transaction lock을 먼저 획득하도록 보완했다. 이후 대상별 lock을 추가로 획득하고 최고 관리자 수를 다시 계산한다.

### 6. 자기 역할 변경

자기 역할 변경은 실수와 감사 회피 위험이 있으므로 수준과 관계없이 거부한다. 단일 최고 관리자는 다른 최고 관리자를 먼저 지정한 뒤 타인에 의해서만 역할을 변경할 수 있다.

### 7. 고위험 제재 경계

초기 문서의 720시간 기준은 운영 위험이 과도했다. 최종 기준은 168시간이다.

- 168시간 이하 계정 활동 제한: 관리자 이상
- 168시간 초과: 최고 관리자
- 조기 해제: 최고 관리자

댓글·신고 제한은 기존 최대 365일 계약을 유지한다.

### 8. 이의제기 수용과 기각

기각은 원결정 유지이므로 관리자 이상, 수용은 원결정 취소이므로 최고 관리자 전용이다. RPC가 decision 값에 따라 capability를 분기한다.

### 9. 화면과 DB 권한 불일치

화면의 버튼 숨김만으로는 직접 RPC 호출을 막지 못한다. middleware, 서버 액션, RPC를 같은 capability 이름으로 연결하고 DB를 최종 gate로 유지한다.

### 10. 통합 감사의 민감 정보

서로 다른 원장의 원문을 단순 노출하지 않는다. 통합 감사 RPC는 정규화된 요약만 반환하고 관리자 이상만 조회한다. 상세 원문은 기존 전용 운영 화면에 남긴다.

### 11. 사용자 검색 개인정보

역할 대상 검색은 display name과 UUID만 사용한다. 이메일은 반환하지 않으며 검색어 최소 2자, 결과 최대 50개로 제한한다.

### 12. bootstrap 데이터

기존 production admin은 migration에서 최고 관리자 implied-role로 정규화하고 이관 사실을 감사 원장에 기록한다. 이후 브라우저의 직접 역할 쓰기는 허용하지 않는다.

### 13. 마이그레이션 재현성

Hosted 최초 적용에서 bootstrap INSERT의 untyped `NULL`이 UUID 컬럼과 충돌했다. 저장소 migration에 `NULL::UUID` 및 TEXT 명시 캐스트를 적용해 신규 환경과 Hosted 적용 계약을 일치시켰다.

4. 전역 lock 기반 역할 변경 직렬화
5. 마지막 최고 관리자 보호
6. 자기 역할 변경 금지
7. 168시간 초과 계정 정지 최고 관리자 전용
8. 제재 해제와 이의제기 수용 최고 관리자 전용

10. 통합 감사 최소 정보 노출
