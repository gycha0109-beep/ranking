# P1-2.7 최종 게이트 리뷰

## 구조 판단

현재 구조는 제재 원장, 이벤트 원장, 상태 projection, 이의제기, 이의제기 결정을 분리한다. 과거 결정을 덮어쓰지 않으면서 현재 효력을 빠르게 조회할 수 있어 운영 감사성과 실행 성능의 균형이 적절하다.

## 보안 판단

- API 역할의 직접 테이블 접근을 차단했다.
- 사용자 조회는 본인 RPC로 한정했다.
- 관리자 RPC는 데이터베이스에서 `is_admin()`을 다시 검증한다.
- 댓글·신고·engagement 쓰기는 테이블 mutation boundary에서 capability를 검사한다.
- 계정 활동 제한 중에도 본인 제재 조회와 이의제기는 허용한다.
- 관리자 계정에 대한 제재 생성은 거부한다.

## 무결성 판단

- 같은 제재 종류의 동시 중복 생성을 advisory lock으로 직렬화한다.
- 제재당 이의제기는 하나만 허용한다.
- 제재 원장과 결정 원장은 수정·삭제할 수 없다.
- 만료와 이후 원결정 취소를 별도 이벤트로 보존한다.
- 현재 상태는 projection에서만 변경한다.

## 결론

Hosted smoke 검증과 exact-head CI가 통과하면 PR 병합 승인 요청이 가능하다. 사용자 명시 승인 전에는 병합하지 않는다.
