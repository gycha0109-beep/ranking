## Publication contract

The batch reused the existing CONTENT-1/OPS-1 domain contract without new schema or RPC work:

- `ranking_type='metric'`;
- explicit `scope_json.target / period / method`;
- at least one complete criterion;
- authoritative public source rows;
- contiguous `TOP 5` entries;
- public reason for every entry;
- active canonical items only;
- metric value stored in `score_json.scores`;
- rating-style `editor_score` left null;
- `private.ops_1_ranking_editorial_readiness` evaluated for every draft before publication.

The batch was authored inside a fail-closed transaction. Publication was attempted only after all four drafts returned `editorial_ready=true` with zero blockers.

## Operational failure exposed

The first transaction attempted to provide `categories.search_name` explicitly. That column is generated by PostgreSQL, so the transaction failed with a generated-column write error.

Because the operation was a single transaction, the first attempt rolled back completely. A readback confirmed that zero CONTENT-2 ranking rows remained. The second attempt omitted generated columns and succeeded.

This was an authoring-script mistake rather than a product/schema contract defect. No incomplete or partially published CONTENT-2 document was exposed.

This is roughly ten minutes of AI-assisted batch wall-clock for source selection, source verification, schema/preflight inspection, canonical item authoring, rollback recovery, readiness evaluation and publication. It is not a human manual-authoring benchmark.

## Bottleneck conclusion

CONTENT-2 expanded from one editorial domain to three top-level categories overall and added four source-backed documents without introducing new ingestion infrastructure.

The batch did not demonstrate that external fetch/import/crawling is currently the limiting factor. Source verification and structured authoring remained manageable within the existing OPS-1 workflow. P2-4 external ingestion therefore remains deferred.
